# 数学建模 · 华为杯研赛协作仓库

> 三人按 **建模 / 编程 / 写作** 分工，各写各的主阵地，互不干扰。
> 本文件是**协作规约**，三人开工前必读。

## 一、分工与主阵地（各自只写自己的，别人只读）

| 角色 | 主阵地（只写这里） | 职责 |
|---|---|---|
| **建模手** | `建模/` | 读题、建模、写每问思路+公式（`建模/q1_建模.md`…） |
| **编程手** | `src/` `data/` `figures/` `results/` | 把模型实现成代码、处理数据、出图、出结果，并负责仓库能跑通 + 环境说明 |
| **写作手** | `paper/` `协作/` | 论文正文、排版、写分工表、记会议纪要 |

> 核心规矩：**一个人的文件只写不碰别人的；别人对你的文件一律只读。**
> 要动别人的文件 → 先在群里说一声。

## 三、Git 协作规约（防冲突）

1. **主分支 `main`**：随时保持可用、是当前最完整版本，谁都能 pull。
2. **工作流**：先在 main 上 `git pull` 拿最新 → 改**自己主阵地**的文件 → `git add` + `git commit` → `git push`。
3. **一条铁律**：push 前**先 pull**（`git pull`），有冲突先解决再 push。
4. **不在别人的目录里动文件**（这是最有效的冲突预防）。
5. **提交信息写清**：如 `solve q2: 跑通评价函数`，别只写 `update`。
