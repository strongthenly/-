# 调用规范

## GPT-6执行约定

在Codex中选择GPT-6 Astra；不要靠提示词声称已切换模型。推理档位采用当前可用设置，复杂模型论证可提高档位，但高档位不是质量证明。记录模型、日期、工具能力、环境版本和预算。用户说“还剩12%”时，把它当作资源约束，不换算成未经读取的token余额。

指令应写清目标、数据、范围、检查和交付；不要反复堆“顶级专家”“确保一等奖”“必须创新50%”。允许常规可逆决策自主推进，关键缺失才提问；技能只是助手。请求中的新增意见默认补充当前目标，明确取消或切题才替换任务。

## 五种可复制调用

**完整新题**：

```text
使用 $gpt6-math-modeling。原题和附件在<路径>，在<独立新项目>完成全部问题。
先核对提交要求、变量单位、约束与数据结构，再实现基线和针对性改进。
首稿前不阅读同题获奖方案。保存随机种子和划分，独立检查可行性及指标。
交付LaTeX PDF、指定答案文件、代码与图件。结果从同一冻结文件写入摘要/图/表。
保留失败与适用边界，完成逐页渲染；每阶段更新HANDOFF.md。
```

**续做**：

```text
使用 $gpt6-math-modeling。读取<项目>/HANDOFF.md和最新结果清单。
核对已有版本与待办后继续。保留上一版，优先解决记录中的最高影响风险。
不要重新搭环境或重跑已验证且未改变的实验。
```

**5—10分钟评审**：

```text
使用 $gpt6-math-modeling，评审<PDF及结果目录>。
先按摘要、主图表、强基线和论证边界判断，再核对最可能改变结论的证据。
输出分级问题与修订优先级，区分已验证错误和待核验猜测。暂不修改文件。
```

**有限资源修订**：

```text
使用 $gpt6-math-modeling。保留当前版；在本轮资源内交付一个能打开的修订版。
先选一到两项最能改变结论的实验，复用冻结预测器或可行解。
预留编译、逐页检查和交接时间；没有新证据的润色后置。
不把未运行实验写成已完成，不为获得漂亮数字改测试口径。
```

**三人协作的建模手**：

```text
使用 $gpt6-math-modeling，按仓库现有角色边界，仅修改建模目录。
输出每问的变量、公式、假设、算法接口、合法基线、验证标准及需要编程手产出的结果字段。
读取其他目录了解进度，但跨角色修改和对外通信需有明确授权。
```

## 提供给模型的最小信息

原题及附件路径；比赛/练习/研究模式；本轮工作范围；输出目录；已有版本入口；硬性时间/页数/格式要求（如有）。没有原始数据就只能完成模型设计，不能虚构运行指标。API密钥通过目标环境自己的凭据机制提供，不放提示词或仓库。

## 交接的完成标准

用户能找到最新版、知道哪个结果已冻结、知道如何复现、知道下一步是什么。某个难点暂时无法解决不意味着整篇停工：完成可独立完成的部分，并准确列出阻碍与所需条件。
